## Objective

Put the Expo client's package in the repo so 3a.2 (foundations) has a place to
land code — and prove, in CI, that the whole toolchain agrees on it: the pnpm
workspace resolves the client, the client consumes the generated TypeScript from
`@ocf-ims/protocol-buffers`, TypeScript 6 typechecks it, biome lints it, Jest runs a
render test through `jest-expo`, `expo export -p web` produces a static site, and
Playwright loads that site. **Nothing product-shaped ships here** — one route that
renders the app name and the `ImsService` type name, which is the smallest possible
proof that the codegen wiring works end to end.

After this slice, 09i §9's client protocol runs green from a fresh clone:

```bash
pnpm install --frozen-lockfile
pnpm generate
pnpm -F @ocf-ims/interface typecheck
pnpm lint
pnpm -F @ocf-ims/interface test
pnpm -F @ocf-ims/interface export:web
pnpm -F @ocf-ims/interface e2e
```

## Decisions (architect, signed off)

| # | Decision | Why |
|---|---|---|
| S1 | **`create-expo-app --template blank-typescript@57` + Expo Router installed by hand** (the documented "manual installation"), not the `tabs`/`default` template. | The router templates ship a themed component set and example screens we would delete anyway (09i G3: a redesign, not a port). Blank + router leaves exactly the tree 09i §5 describes. |
| S2 | **pnpm hoisted linker** (`node-linker=hoisted` in the root `.npmrc`). No Metro config file. | Expo's monorepo guide requires the hoisted layout for pnpm; SDK 52+ detects the workspace and configures Metro (watch folders, resolver paths) itself. The one line in `.npmrc` is the whole monorepo setup. |
| S3 | **`@ocf-ims/protocol-buffers` exposes its generated `src/` through a package `exports` map** (`"./*": "./src/*.ts"`), consumed as raw TypeScript. | No build step for the proto package: Metro transpiles workspace TS, `tsc` (`moduleResolution: bundler`) and Jest resolve `exports` to `.ts` targets. Import shape: `@ocf-ims/protocol-buffers/ocf/ims/service/v1/service_pb`. |
| S4 | **Playwright smoke runs against the web export served by `expo serve`**, not the docker stack. | The compose-stack smoke (login → … → logout) is 3a.3's deliverable and needs screens that do not exist yet. The scaffold proves "the export renders in a browser"; 3a.3 swaps the target. The repo-root `playwright/` (templ specs) is untouched until then. |
| S5 | **`web.output = "single"`** (SPA) and `scheme = "ocfims"`. | E9 serves the export from a static container with an SPA fallback; E15 reserves the `ocfims://` deep-link scheme. Typed routes stay off until 3a.3 has routes. |
| S6 | **The Apache header goes on every `.ts` and `.tsx` file** the client adds, and the `prepend-license` hook learns `.tsx`. | The hook already stamps `.ts` (and fails the Linters job when a file lacks the header); the client tree will be mostly `.tsx`, so the rule extends rather than splits. Generated files (`// @generated by`) stay exempt. |
| S7 | **`pnpm generate` is a root script** = `cd go && go tool buf generate --template ../buf.gen.web.yaml ../proto`. | The E1 rule: generated TS is gitignored, so the client's typecheck must run the generator first, and it must be one command a fresh clone can find. |
| S8 | **The `Interface` CI job is a fourth job** in `cicd.yml` with its own hardened-runner allow-list (npm registry, Go proxy for `go tool buf`, the Playwright CDN). `EXPO_OFFLINE=1` and `EXPO_NO_TELEMETRY=1` so the Expo CLI never phones home from CI. | E12. Store builds never run in CI. |
| S9 | **Imports: a `@/*` → `src/*` alias (tsconfig `paths`, mirrored in `jest.config.js`); generated protos stay deep-imported; no barrel files.** Miguel's call after comparing with maybloom (2026-09-09): maybloom has no barrels step for its protos either — it deep-imports through the same kind of `exports` map (built with tsup because Node and Vite consume it), imports its own code with relative paths, and keeps a few hand-written component barrels. We take the alias, skip the barrels. `src/lib/app.ts` (`APP_NAME`) is the alias's wiring proof through tsc, Metro and Jest. | Metro reads tsconfig paths natively (SDK 50+); it does not tree-shake, so a barrel over the generated tree would drag every message into every bundle. Recorded as a §5 rule in 09i. |

## Build notes — what the brief got wrong, and who fixed it

The mechanic (Haiku) executed steps 1–15 as written and stopped at 16 with a clear
report: typecheck, Jest and `expo export` all failed on a missing
`buf/validate/validate_pb` module. That was the right call (09i §7 rule 1: report,
don't improvise). The architect then fixed the following on top of the mechanic's tree:

1. **The proto TypeScript was never complete** (not a scaffold problem).
   `buf.gen.web.yaml` generated only the contract module; every `*_pb.ts` imports the
   protovalidate rules from the vendored `third_party/protovalidate` module, which
   was never emitted. `include_imports: true` on the protoc-gen-es plugin generates it
   (`packages/protocol-buffers/src/buf/validate/validate_pb.ts`); `include_wkt` stays
   off because protoc-gen-es imports the well-known types from `@bufbuild/protobuf/wkt`.
   The Go template is unaffected (Go imports protovalidate's published module). The
   Phase-0 target had had dangling imports since slice 0a — nothing consumed it until now.
2. **TypeScript 6 does not include `@types/*` automatically.** The template pins
   `typescript ~6.0.3`; `tsc` could not see `describe`/`it`/`expect`. The mechanic's
   guess (`types: ["jest", "@testing-library/react-native", "@playwright/test"]` +
   `skipLibCheck`) was narrowed to `types: ["jest"]` — the other two are imported, and
   `expo/tsconfig.base` already sets `skipLibCheck`. Also: overriding `exclude` replaces
   the base's list, so `jest.config.js`, `android`, `ios` are re-listed beside `dist`.
3. **RNTL 14's `render` is asynchronous.** The synchronous form the brief described
   fails with "not implemented" from `screen`; the test now `await`s `render`.
4. **`newArchEnabled` is not in the SDK 57 config schema** (`expo-doctor` rejects it);
   the New Architecture is the only one. Dropped from `app.json`; E2 unchanged in intent.
5. **biome 2 finds the root config from the package directory**, so `lint` is plain
   `biome check .` (no `--config-path`). Its `vcs.useIgnoreFile` also honours the
   package-local `.gitignore`: `dist/`, `.expo/` and the Playwright output need no
   `!` entries.
6. **Playwright config typing**: the reporter list must be tuples
   (`[["list"], ["html", …]]`), and `page.getByText` replaces the legacy `text=`
   selector. The `Interface` job's `env` moved above `steps`, gained comments, and
   `actions/setup-node` was pinned to the current major (v7).
7. The three `.tsx` headers lacked the framing `//` lines of the canonical block;
   normalised so the client tree matches `go/` and `web/typescript` byte for byte.

`expo-doctor` did not flag `@expo/metro-runtime`; the web export worked with `react-dom`
+ `react-native-web` alone (SDK 57 bundles the runtime).

## Findings

Recorded in plan 09 §7 ("3a.1 — the Expo client's package and toolchain"); the short form:

- **A generated target nobody compiles against is not verified.** The TS proto output
  had dangling imports from slice 0a until its first consumer. `include_imports` is the
  fix; the lesson is 09i G1.
- **TypeScript 6 changed the `types` default**; **RNTL 14 made `render` async**;
  **SDK 57 removed `newArchEnabled`.** Three "current version" facts the brief had wrong
  from training-era memory — each caught by running the tools, which is what a scaffold
  slice is for.
- **The monorepo cost is one `.npmrc` line and one `exports` map.** No Metro config, no
  build step for the proto package, and `tsc`, Metro and Jest all resolve the raw `.ts`
  the same way.
- **The mechanic tier worked as designed**: a precise brief, executed literally, with a
  stop-and-report on the first surprise — the architect's time went to the four real
  problems, not the forty mechanical steps.
